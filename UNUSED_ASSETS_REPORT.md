## Метод и ограничения

Проверены все 550 файлов public (225.06 MiB), точные URL в src и текстовых public assets, готовый HTML обычных страниц и связанные CSS/JS/manifest; preview HTML рассматривается отдельно. Результаты по каждому файлу: `artifacts/performance/inventory/assets-before.json`. Наличие ссылки в старом source-модуле не означает загрузку в браузере; отсутствие точной ссылки не доказывает безопасность удаления: возможны относительные пути, динамические URL, внешние ссылки и сохранённые закладки.

Без прямых ссылок из production-страниц найдено 344 файлов (177.79 MiB); это кандидаты для ревью, а не автоматически разрешённое удаление.

Число344 — сырой результат эвристики прямых ссылок. Из вывода «не используется» необходимо исключать неявные публичные entrypoints: `robots.txt`, sitemap, web manifest, `/favicon.ico` и объявленные platform icons. Они могут запрашиваться crawler/browser/ОС без ссылки из HTML и должны сохраняться; архивирование таких entrypoints не рекомендуется.

## Копирование в build

Astro копирует public целиком: исходная dist до оптимизации содержала 665 файлов (228.03 MiB), включая 66 файлов внутри previews. Папки assets, artifacts, docs и screenshots в корне не копируются автоматически. Большие исходные PNG в public увеличивают размер deployment, даже когда браузер получает оптимизированный WebP.

Рекомендация: исключить dev previews/QA HTML и public/previews из публичного build, сохранив исходники. Для старых source assets предпочтителен архив вне public с отдельным решением владельца: не удалять в первом проходе.
