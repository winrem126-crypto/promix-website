# Проверки PROMIX

Нужны Node.js 22.12+ и зависимости из lock-файла. Браузерные проверки используют установленный Google Chrome и devDependency Playwright 1.62.1. Для полного набора установите Chrome обычным способом: проверки согласия используют канал `chrome` и не читают `PROMIX_CHROME_PATH`. Проверки сайта и API поддерживают путь к совместимому браузеру через `PROMIX_CHROME_PATH`.

```text
pnpm install --frozen-lockfile
pnpm run build
pnpm test
pnpm run test:api
```

`pnpm test` запускает модульные проверки заявок, SEO, матрицу согласия и общую браузерную приёмку свежего `dist`. `pnpm run test:site` повторяет только проверку сайта. Перед тестами сайта требуется успешная сборка: тестовый HTTP-сервер обслуживает именно `dist`, не исходники dev server.

Приёмка API требует PHP с `mbstring` и `openssl`, а также установленный `backend/vendor` из `composer.lock`. Она создаёт временную копию backend и отдельную приватную конфигурацию, поднимает PHP и SMTP-приёмник только на `127.0.0.1` и использует адреса `example.invalid`. Production-конфигурация не читается и не меняется, реальные письма не отправляются. Все временные процессы и каталоги закрываются после проверки. При отсутствии необходимых инструментов проверка завершается ошибкой, а не выдаётся за пройденную.

Необязательные параметры: `PHP_BINARY` — PHP; `PROMIX_PLAYWRIGHT_MODULE` — отдельный модуль Playwright для API-приёмки; `PROMIX_CHROME_PATH` — браузер; `PROMIX_QA_DIR` — каталог скриншотов и JSON общей приёмки. По умолчанию артефакты сайта пишутся в соседний с проектом `PROMIX_FIX_QA_2026-10-26`, вне `dist`.

Наборы:

- `lead-submissions.test.mjs`: идентификация запросов, независимые изменённые заявки, повтор прежнего ID, неопределённые и успешные состояния, TTL и сбои хранения.
- `lead-api-acceptance.mjs`: реальный PHP/PHPMailer и локальный SMTP, 422/429/409/503, неопределённый SMTP-исход, UTF-8, защита логов и браузерный транспорт.
- `consent-browser.test.mjs`: production hostname с локальными моками, оба порядка модулей, новые и вернувшиеся посетители, отказ/разрешение, ограничения хранилищ, отмена загрузки и целей, UTM.
- `product-seo.test.mjs`: все прямые товарные страницы, уникальные содержательные метаописания.
- `site-browser.test.mjs`: все 37 русскоязычных страниц, текущие 26 видимых товаров и сохранённые прямые страницы, оба H 0,2 и их поиск, фасовки четырёх SUPER TACK, ссылки/медиа/sitemap/robots, семь ширин, меню, cookie, skip-link, пять этапов, фокус диалога и скачивание исходного PDF.
- `i18n-browser.test.mjs`: 407 HTML-страниц на 11 языках, canonical/hreflang/SEO, названия и числовые характеристики всех 30 товаров; поиск, фильтры, валидация и переключение языка с сохранением параметров и якоря на десяти переводах; ширины 1440/1101/390/320, клавиатура и ссылки без JavaScript. Артефакты записываются вне проекта в `PROMIX_I18N_QA_2026-10-27` либо в `PROMIX_I18N_QA_DIR`.

После уточнения от 26 октября каталог содержал 25 видимых товаров и 8 шпатлёвок. Задание от 27 октября возвращает самостоятельную красную H 0,2 — Жёсткая; текущая приёмка ожидает 26 карточек и 9 шпатлёвок. Синяя H 0,2 сохраняет прежний URL, H 0,3 и остальные ранее скрытые товары остаются скрытыми; их прямые страницы сохранены. Счётчики интерфейса выводятся из общего списка видимых товаров.

Локальный SMTP-приёмник подтверждает работу доступной цепочки, но не доставку в рабочий почтовый ящик. Финальная проверка публичного API, TLS, SMTP/DNS и фактического получения письма выполняется отдельно по `deploy/SMTP_PRODUCTION_CHECKLIST.md`.
