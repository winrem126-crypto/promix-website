# PROMIX

Сайт строительных материалов PROMIX: каталог товаров, фотографии, документы и формы заявок. Статическая часть построена на Astro 7 и TypeScript; заявки обрабатывает отдельный PHP API с PHPMailer. Исходники, изображения и необходимые документы находятся в этом репозитории.

Версия после аудита 26.10.2026: исправлены 12 групп замечаний, пройдены 100 тестов (90 основных и 10 API). Каталог содержит 25 активных товаров; прямые страницы сохранены для 29 товаров. Решения о скрытых товарах зафиксированы в `deploy/OWNER_DECISIONS_2026-10-26.md`.

## Локальный запуск

Нужны Node.js >=22.12.0 и pnpm 11 (проверенное окружение: Node.js 24.19.0, pnpm 11.25.0).

```sh
pnpm install --frozen-lockfile
pnpm run dev
```

Сайт откроется по адресу <http://localhost:4173>. Для статического сайта SMTP-настройки не нужны.

## Сборка и проверка

```sh
pnpm run build
pnpm run preview
pnpm test
pnpm run test:api
```

Сборка включает `astro check` и создаёт `dist/`. Preview показывает готовую статическую сборку. Тесты запускаются после сборки; полному набору нужен установленный Google Chrome (матрица согласия использует канал `chrome`). Проверки сайта и API также поддерживают переменную `PROMIX_CHROME_PATH` с путём к совместимому Chromium. При необходимости отдельно: `pnpm run check` и `pnpm run test:site`.

Для API-тестов нужны PHP 8.1+ с JSON, OpenSSL и mbstring, Composer и зависимости backend:

```sh
composer install --working-dir=backend --no-dev --optimize-autoloader
```

При нестандартном расположении PHP задайте `PHP_BINARY`. API-тесты сами запускают временный PHP-сервер и SMTP-приёмник на loopback; реальные письма не отправляются. Диагностические результаты браузерных проверок по умолчанию создаются в соседней папке `PROMIX_FIX_QA_2026-10-26`, вне репозитория; расположение можно изменить через `PROMIX_QA_DIR`.

## Структура и конфигурация

- `src/` — страницы, компоненты, стили, клиентские сценарии и данные товаров.
- `public/` — рабочие изображения, шрифты, PDF и статические файлы.
- `assets/` — исходники графики; `accepted-concept.png` — утверждённый дизайн.
- `backend/` — API; Composer lock и безопасный `config/config.example.php`.
- `tests/` — автоматические проверки и локальные стенды.
- `scripts/`, `docs/`, `deploy/` — подготовка ресурсов, техническая документация и инструкции приёмки.

Реальные доступы храните вне Git. `.env.example` содержит безопасный перечень переменных. PHP не загружает корневой `.env` автоматически: используйте окружение PHP или приватный `backend/config/config.php`, созданный из примера. Конфигурация, зависимости, состояние заявок, сборки, кэши, логи, резервные архивы и результаты QA исключены через `.gitignore`.

Для ручной проверки форм запустите отдельно `php -S 127.0.0.1:8080 -t backend/public` с приватной тестовой конфигурацией: Astro dev проксирует `/api/` на этот сервер. Подробности, ограничения повторной отправки и настройки хранилища — в `backend/README.md`.

## Последующее развёртывание

GitHub хранит исходники; автоматическое развёртывание не настроено. Статический хостинг не исполняет PHP. Перед публикацией нужны настройка PHP/Nginx, приватные SMTP-доступы, постоянное защищённое хранилище и проверка доставки в реальный ящик по `BACKEND_DEPLOY.md` и `deploy/`. Готовность технических документов и оставшиеся ограничения описаны в `docs/PRODUCT_DOCUMENT_READINESS_2026-10-26.md`.

`README_TRANSFER.md` и `README_RELEASE.md` описывают прежние этапы переноса и выпуска. Для текущих зависимостей и команд используйте этот README и lock-файлы. Некоторые исторические утилиты подготовки графики содержат пути прежнего рабочего окружения; для dev, build и тестов они не требуются.
