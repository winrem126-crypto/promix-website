# PROMIX — performance budget

Ограничения выбраны по production baseline и сохранению качества реальных этикеток. Проверять только production-сборку, одинаковыми профилями до/после; исходники изображений и содержимое PDF не менять ради выполнения бюджета.

## Ограничения загрузки

| Показатель | Бюджет | Основание |
|---|---:|---|
| Initial JS одной страницы | ≤25 KiB raw / ≤9 KiB gzip | Vanilla JS без hydration; все runtime chunks исходной сборки вместе занимали 53,5 KiB |
| Initial CSS главной | ≤140 KiB raw / ≤30 KiB gzip | После удаления проверенных старых компонентов; интерактивные состояния форм/меню сохраняются |
| Initial CSS каталога / продукта | ≤120 KiB raw / ≤25 KiB gzip | Общий shell и стили текущей страницы |
| Initial CSS документов / legal | ≤90 KiB raw / ≤18 KiB gzip | Без каталожного CSS/JS |
| Hero главной | ≤150 KiB | Утверждённый WebP:129774 байта; более тяжёлые experimental derivatives отклонены |
| Product LCP при390px/DPR1.75 | ≤220 KiB | Подбирать640px при достаточной фактической плотности; этикетки важнее произвольного процента сжатия |
| Product640 /960 WebP | ориентир≤220 /420 KiB | Lossless, полная прозрачность; исключения требуют визуальной проверки и объяснения |
| First-load transfer главной | ≤1.5 MiB | Baseline mobile4.08 MiB; замер load+1.8s, Fast4G, без scroll |
| First-load transfer каталога | ≤1.5 MiB | Baseline desktop3.09 MiB; одинаковые маски должны использовать один URL |
| Запросы до конца начального snapshot | главная≤35; каталог≤55; продукт≤25; документы≤16 | Cold load; поздние lazy-запросы и cache учитывать отдельно |
| Preload | ≤2 на страницу | Один реально используемый основной WOFF2 и не более одного LCP image; никаких preload всех товаров |
| High priority images | ≤1 | В каталоге выбирать фактически первый видимый товар после восстановления URL state |
| Third-party до согласия | 0 requests /0 bytes | Метрика только после analytics consent |
| First-party initial fonts | ≤150 KiB | Только существующие WOFF2; без дублирования URL, italics и дополнительных языковых subsets |
| Initial PDF | 0 requests /0 bytes | Только переход/скачивание по действию пользователя |

Размеры выше относятся к конкретному viewport и DPR. Нельзя искусственно выбирать слишком маленькое изображение ради бюджета. Для высокого DPR браузер вправе выбрать960/1600px. Текущие исходники до2048px и утверждённый hero1207×1303 сохраняются; новый source больше2048px требует обоснования. `srcset/sizes` должен описывать весь прозрачный canvas, а не только видимую этикетку.

## Метрики качества

| Метрика | Цель |
|---|---:|
| Lighthouse Performance | ≥90 mobile и desktop, cold load |
| LCP | ≤2500ms |
| CLS | ≤0.1; ожидаемый уровень текущего сайта≤0.01 |
| Field INP | ≤200ms на75-м процентиле после достаточного реального трафика |
| Lab TBT | ≤200ms; ожидаемо≤100ms |
| FCP | ориентир≤1800ms mobile /≤1000ms desktop |
| Best Practices | 100, без критических ошибок |
| JS exceptions /resource404 | 0, кроме специально проверяемого отсутствующего URL |

Field INP не заменять TBT, временем клика или значением Lighthouse. Slow4G Lighthouse и Fast4G Playwright — разные лабораторные профили; их абсолютные значения нельзя смешивать. Кешированный запуск оценивать отдельно от cold load. Если цель не достигнута, фиксировать фактическое значение и причину в `PERFORMANCE_AUDIT_AFTER.md`, а не повышать порог задним числом.

## Сборка и публикация

- Production build: существующая команда `pnpm run build`;0 errors/warnings/hints.
- Размер всего `dist/`: верхняя граница240 MiB на этом проходе. Оригинальные assets сохранены по условию задачи; этот размер не равен трафику первого открытия. Очистку исходных неиспользуемых assets рассматривать отдельно по `UNUSED_ASSETS_REPORT.md`.
- Baseline build71.092s; ориентир≤80s на этой же машине. Время зависит от filesystem/кешей; ускорение не считать гарантией для другой машины.
- В release не должно быть preview HTML, QA screenshots/архивов, `.env`, source maps, абсолютных локальных путей и секретов.
- Все26 карточек,30 product URLs, тексты, product data и официальный PDF должны сохраняться. Проверять контрольные суммы и rendered text, а также desktop/mobile регрессии.
- Hashed assets: годовой immutable cache; HTML — revalidation; обновляемый PDF — сутки с revalidation. Это серверные настройки, их применение проверяется на FirstVDS отдельно.

Повторяемые лабораторные команды и настройки сохранены в `artifacts/performance/browser-audit.cjs` и `lighthouse-audit.mjs`. Обязательные страницы, реальные LCP-элементы, HAR и до/после находятся в audit-отчётах. Автоматической публикации или обращения к рабочему SMTP здесь нет.
